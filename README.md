# 👹 ПИЩЕБЛОК-200 | Учебный помощник

Учебный Telegram-бот группы ПКД-1 на Python 3.12 и aiogram 3. Он получает обновления через long polling и сохраняет расписание, настройки и кабинеты в SQLite. Студенты открывают разделы из закреплённого меню в теме группы. Старосты редактируют расписание в личном чате с ботом.

## 1. Подготовь доступы

1. В Telegram открой [@BotFather](https://t.me/BotFather). Отзови раскрытый токен своего бота командой `/revoke` и получи новый. Если BotFather предложит выбрать бота, выбери существующего, чтобы сохранить его имя и доступ к ранее загруженным фото. Храни новый токен только в переменных Railway или локального процесса.
2. Останови старый запуск в Colab, на компьютере или другом сервере. Для одного токена должен работать один процесс. Второго бота с отдельным токеном и отдельной базой можно использовать для проверки.
3. Подготовь числовые Telegram ID двух старост. `ADMIN_IDS` принимает положительные ID через запятую, например `111111111,222222222`. Подставь настоящие ID вместо примера.
4. Если нужна старая база, скачай из Google Drive резервную копию `pkd1_bot.db` после остановки старого процесса. Если рядом есть `-wal` или `-journal`, сделай согласованную копию через SQLite Backup API, пока все связанные файлы доступны. Команда ниже работает из папки со старой базой и создаёт отдельный файл. Запускай её с новым именем файла назначения, если это имя уже занято.

```powershell
python -c "import sqlite3; a=sqlite3.connect('file:pkd1_bot.db?mode=ro', uri=True); b=sqlite3.connect('pkd1_backup.db'); a.backup(b); print(b.execute('PRAGMA integrity_check').fetchone()[0]); b.close(); a.close()"
```

## 2. Загрузи проект на GitHub

1. Распакуй архив в отдельную папку, например `Документы\pischeblok-200`. Если ты уже открыл папку проекта в Codex, можешь использовать её. На GitHub загружай содержимое этой папки, где лежит `Dockerfile`.
2. Создай пустой **Private**-репозиторий на GitHub, например `pischeblok-200`. Оставь галочки создания README, .gitignore и лицензии выключенными.
3. Установи [Git](https://git-scm.com/downloads), открой PowerShell в папке проекта и выполни команды. Вместо `USERNAME` подставь свой логин. Перед коммитом просмотри имена файлов в `git status --short`. Там должны быть код, README и настройки проекта. Держи исходный TXT, настоящие токены, базу и копии базы вне репозитория.

```powershell
git init -b main
git add .
git status --short
git commit -m "Подготовить бота к Railway"
git remote add origin https://github.com/USERNAME/pischeblok-200.git
git push -u origin main
```

Если Git просит имя и почту автора, укажи их через `git config user.name "Имя"` и `git config user.email "email"` из этой папки. После загрузки проверь, что в корне репозитория виден `Dockerfile`. [Инструкция GitHub по загрузке существующего проекта](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).

## 3. Создай сервис и том в Railway

1. Войди в [Railway](https://railway.com/) через GitHub. Нажми **New Project → Empty Project**, затем выбери **New → Empty Service**. Открой **Settings** сервиса, в разделе **Source** нажми **Connect Repo** и выбери `pischeblok-200`, ветку `main`. Если репозитория в списке нет, выдай приложению Railway в GitHub доступ именно к нему. [Подключение источника Railway](https://docs.railway.com/services).
2. Добавь **Volume** к этому сервису через **New → Volume** или меню сервиса, если оно предлагает **Attach Volume**. Укажи **Mount Path** `/data`. Если нужно перенести старую базу, сначала выполни раздел ниже. Railway запускает сервис с томом в одном экземпляре. При обновлении с томом возможна короткая пауза. [Тома Railway](https://docs.railway.com/volumes).
3. В **Variables** добавь `BOT_TOKEN` с новым токеном и `ADMIN_IDS` с ID старост. Укажи `DB_PATH=/data/pkd1_bot.db`. Если загружал старую базу под именем из следующего раздела, укажи `DB_PATH=/data/pkd1_import.db`. Добавь `RAILWAY_DEPLOYMENT_DRAINING_SECONDS=15`, чтобы процесс успел закрыть сессию по SIGTERM, и `RAILWAY_DEPLOYMENT_OVERLAP_SECONDS=0`. [Переменные Railway](https://docs.railway.com/variables/reference).
4. В **Settings** сервиса проверь **Restart Policy → On Failure** и лимит **10**. Оставь один регион и одну реплику. Держи **Serverless** выключенным. Поля **Public Networking**, **Healthcheck Path** и **Start Command** оставь пустыми. Сохрани изменения и нажми **Deploy**, если Railway показывает ожидающие изменения. Railway обнаружит `Dockerfile` и запустит `python main.py`. [Политика перезапуска](https://docs.railway.com/deployments/restart-policy) · [Dockerfile в Railway](https://docs.railway.com/builds/dockerfiles).

`railway.example.ts` показывает конфигурацию Infrastructure as Code для нового проекта. При настройке через интерфейс этот файл можно оставить как пример. Вариант для CLI требует подставить владельца GitHub-репозитория, сохранить файл как `.railway/railway.ts` и проверить план через `railway config plan`. [Infrastructure as Code](https://docs.railway.com/infrastructure-as-code).

### Перенос старой SQLite

1. Сохрани оригинал отдельно. Проверь резервную копию командой из пункта 1. Результат проверки должен быть `ok`.
2. Установи [Railway CLI](https://docs.railway.com/cli/installation) и открой PowerShell в папке с проверенной копией. Выполни `railway login`, затем `railway link`. В подсказках выбери свой проект, окружение и сервис. Создай и примени изменения с томом до загрузки, а новый токен добавь после загрузки.
3. Выполни команды. В путях CLI корень `/` соответствует смонтированному `/data`. Если CLI предложит выбрать том, выбери том сервиса бота. Имя `pkd1_import.db` должно быть свободным. Для повторного переноса используй другое имя и соответственно измени `DB_PATH`.

```powershell
railway volume files list /
railway volume files upload ./pkd1_backup.db /pkd1_import.db
railway volume files list /
```

4. Укажи `DB_PATH=/data/pkd1_import.db` и добавь токен. При старте бот добавит недостающие столбцы SQLite и сохранит существующие строки и настройки. Проверь расписание, сохранённые кабинеты и привязку темы. Старые фото проверяй на том же Telegram-боте, поскольку `file_id` привязан к боту. [Команды управления файлами тома](https://docs.railway.com/cli/volume).

## 4. Проверь работу и публикацию

1. Открой сервис → **Deployments** → активное развёртывание → **View Logs**. Найди `Бот запущен. Часовой пояс UTC+5.`.
2. С аккаунта старосты отправь `/start` в личном чате и проверь, что сразу открылась админка. С обычного аккаунта личный чат должен только подсказать, что расписание находится в закрепе темы.
3. Для проверки публикаций используй тестовую супергруппу с темами, отдельного тестового бота и отдельную SQLite. Выдай боту права на отправку текста, фото и закрепление. Староста отправляет `/set_topic` в нужной теме. Бот подтвердит привязку в личном чате, если староста уже запускал его через `/start`. Повтори команду в той же теме и проверь, что меню обновилось на месте. При переносе в другую тему прежняя привязка действует, пока новое меню не закреплено. Общие посты с расписанием из прежней темы остаются там.
4. В личной админке создай тестовое расписание, проверь предпросмотр и опубликуй. Пусть два участника одновременно нажмут **Расписание** в закрепе, выберут разные дни, нажмут **Обновить** и вернутся в главное меню. Каждый должен видеть только свой экран. Второй участник не должен видеть ни экран первого, ни его переходы. В общем закрепе и ленте ничего не должно измениться. Проверь выходной, неопубликованный день, расписание с фото и четыре заглушки. При публикации из админки новое расписание должно появляться на личных экранах студентов.

Для локальной проверки используй токен тестового бота, тестовые `ADMIN_IDS` и свой `DB_PATH`. При обновлении бот автоматически создаёт в SQLite таблицу для ID личных экранов. При нажатии кнопки бот просит Telegram показать личный экран на месте закрепа. Если Telegram отклоняет замену, бот открывает отдельный личный экран в той же теме. Остальные участники по-прежнему видят общий закреп. Навигация редактирует личный экран на месте, а кнопка **В закреп** закрывает его. Чтобы убрать старые кнопки из уже опубликованного закрепа, староста один раз выполняет `/set_topic` в той же теме.

Расписание использует HTML с пустыми строками между парами. Telegram может не доставить временное сообщение, его удаление или правку, особенно если клиент отключился. Если экран пропал, снова нажми кнопку в закрепе. Если остался личный экран из старой версии, нажми в нём **Главное меню**, чтобы закрыть его. Если фото не загрузилось, бот показывает доступный текст и предлагает обновить экран. Кнопка **Только текст** переключает расписание с фото на текст в том же экране. При сбое отправки бот отвечает всплывающим уведомлением. [Временные сообщения Telegram](https://core.telegram.org/bots/api#ephemeral-messages-and-commands) · [Поддержка в aiogram 3.32.0](https://docs.aiogram.dev/en/latest/changelog.html).

Отображаемое имя самого бота можно обновить командой `/setname` в [@BotFather](https://t.me/BotFather). Текущий username можно оставить для совместимости со старыми ссылками. Новый брендинг меню применяется через код.

### Ввод расписания

Можно писать «матан», «физра» и другие знакомые сокращения. Студенты увидят полные названия. Для параллельной пары укажи одной строкой «Иностранный язык». Бот выведет оба кабинета: немецкий — 13, английский — 17.

Обычный день начинается в 08:30. Со включённым классным часом он идёт с 08:30 до 09:00, а первая пара начинается в 09:05. По исходным правилам бот спрашивает про классный час в понедельник и четверг. Длительность пары и перерывы будней и субботы меняются в **Перерывы и пары**. Ручным временем можно переопределить отдельную пару. Следующая пара продолжает использовать время из стандартной сетки.

```text
1. 09:05–10:40 Биология каб. 12А
2. Физкультура | спортзал
3. —
- Принести форму
```

Номер кабинета можно писать в конце. Если название предмета само заканчивается числом, добавь явный кабинет или используй полное название, чтобы исключить неоднозначность. С длинной подписью к фото бот предложит сократить текст или начать ввод заново и опубликовать текст отдельно. Уже сохранённые длинные записи остаются в базе. В предпросмотре нажми **Опубликовать**. Расписание появится на личных экранах студентов в теме. Отдельное сообщение в группу бот не отправляет.

## 5. Обновления и журналы

В Codex открой папку репозитория, внеси изменения и запусти проверки. Затем отправь коммит в ветку `main`. Railway развернёт его автоматически, если включён GitHub Autodeploy. После обновления посмотри **Deployments** и проверь, что расписание по-прежнему читается с тома.

```powershell
git status --short
git add .
git status --short
git commit -m "Описать изменение"
git push
```

Если бот пропал, сначала посмотри **Build Logs** для ошибок установки или **Deploy Logs** для ошибок запуска. Проверь токен в **Variables**, путь тома `/data`, значения `ADMIN_IDS` и отсутствие соперничающего процесса. Если у бота открывается меню, а публикация не проходит, проверь права в супергруппе и привязку темы. Журналы содержат названия типов ошибок, даты публикаций и технические ID. Черновики админки живут в памяти до перезапуска. Опубликованные записи лежат на томе. [Развёртывания и журналы Railway](https://docs.railway.com/deployments).

## 6. Резервное копирование и восстановление

1. В Railway открой сервис → **Backups**. Создай ручную копию перед переносом и крупными обновлениями. Включи плановые копии, если они доступны на твоём тарифе. Перед восстановлением создай текущий снимок, чтобы можно было вернуться к нему.
2. В **Backups** выбери нужную дату, нажми **Restore**, затем **Details** на холсте проекта. Проверь, что восстановленный том подключается по пути `/data` к тому же сервису, и нажми **Deploy**. Railway сохраняет прежний том отдельно. После запуска проверь `DB_PATH`, расписание на известную дату и доступ к админке.
3. Для переносимой копии SQLite подключись командой `railway ssh` к работающему сервису. Создай копию средствами SQLite. Для каждого снимка используй новое имя.

```sh
python -c 'import os, sqlite3; a=sqlite3.connect("file:" + os.environ.get("DB_PATH", "/data/pkd1_bot.db") + "?mode=ro", uri=True); b=sqlite3.connect("/data/pkd1-export.db"); a.backup(b); print(b.execute("PRAGMA integrity_check").fetchone()[0]); b.close(); a.close()'
```

4. Если проверка показала `ok`, выйди из SSH и с компьютера скачай снимок командой `railway volume files download /pkd1-export.db ./pkd1-export.db`. Храни файл приватно. Для восстановления из такого файла загрузи его под новым именем, например `railway volume files upload ./pkd1-export.db /pkd1_restored.db`, измени `DB_PATH` на `/data/pkd1_restored.db` и нажми **Deploy**. Предыдущий файл базы сохранится. Шаги восстановления меняют SQLite. Сообщения, которые Telegram уже отправил в тему, проверяются отдельно. [Резервные копии Railway](https://docs.railway.com/volumes/backups) · [Railway CLI для томов](https://docs.railway.com/cli/volume).

## 7. Тесты на компьютере

Из папки с `main.py` выполни в PowerShell эти команды. Для тестов нужен Python 3.12. Тесты используют временную SQLite и имитируют Telegram API.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q main.py group_interface.py config.py storage.py schedule.py tests
```

При ручном локальном запуске установи `BOT_TOKEN`, `ADMIN_IDS` и `DB_PATH` в переменных процесса. `.env.example` показывает имена параметров. Для проверки с подключением к Telegram используй отдельного тестового бота и отдельную базу. На Windows укажи путь вроде `$env:DB_PATH = "$PWD\data\pkd1_bot.db"`. Запуск `.\.venv\Scripts\python.exe main.py` начинается с проверки переменных и SQLite.

## Стоимость и ограничения

По состоянию на 17 ноября 2026 года базовый тариф Railway Hobby стоит **$5 в месяц**, включая $5 использования. При большем потреблении оплачивается разница. Расход зависит от памяти, CPU, исходящего трафика, размера тома и резервных копий. Посмотри **Usage** после нескольких дней работы и проверь условия своего плана. [Тарифы Railway](https://docs.railway.com/pricing/plans) · [Стоимость резервных копий](https://docs.railway.com/volumes/backups).

Блокировка процесса действует на экземпляры с одной и той же базой на общем диске. Отдельный компьютер или другой сервис с тем же токеном вызовет конфликт Telegram. Доступ к существующей рабочей базе и реальному боту для тестов не предоставлялся, поэтому первое развёртывание и восстановление нужно проверить по шагам выше.
